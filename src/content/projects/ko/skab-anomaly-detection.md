## 데이터 (SKAB)

- valve1(펌프 출구 밸브 폐쇄) 16개 + valve2(펌프 유입구 밸브 폐쇄) 4개 = **20개 CSV**
- 파일당 약 1,200초, 1 Hz, 센서 8개: Acc1, Acc2(진동 RMS), Current, Pressure, Temperature, Thermocouple, Voltage, RateRMS(유량) + anomaly·changepoint 라벨
- **발견 1 — 이상 시작이 거의 600초 고정**
  - 20개 중 18개가 정확히 600초 (v1_8은 599초, v1_2는 결측 때문에 666초)
  - 실험자가 매번 600초에 밸브를 닫았기 때문 → 모델이 전조가 아니라 "경과 시간"을 배울 위험
- **발견 2 — anomaly-free 파일은 다른 운전 조건**
  - 유량 약 4배(125 vs 32), 온도 약 20도 높음(89.5 vs 69.5), Acc1 노이즈 3.8배
  - 정상 데이터로 섞으면 오히려 방해 → 분석에서 제외
- **발견 3 — 50초 이상 큰 결측이 있는 파일 4개**
  - v1_2(591–665초, 이상 직전), v1_4(668–720초), v1_7(1040–1103초), v2_1(899–961초)
  - v1_2는 이상 시작 순간이 결측에 걸려 가장 어려움

## HW4 (수업 제출) — 한 것

- 1초 간격 재색인 + 선형 보간
- 학습 15개 / 테스트 5개(v1_2, v1_3, v1_4, v1_7, v2_1) 파일로 분리
- z-score 정규화 (학습은 학습 통계, 테스트는 테스트 통계)
- 파일별 PCA → PC1 기여 센서 확인
  - 파일마다 달랐음: Current·Voltage가 주도하는 파일, Acc2, RateRMS, Pressure가 주도하는 파일이 섞여 있음
- 10초 이동평균 + 미분으로 변화 패턴 확인, 변화점 전후 10초 평균 비교
- 핵심 센서로 **RateRMS(유량)·Accelerometer2RMS** 선택
- Hyper Feature (HF = S1 + S2)
  - S1: 유량 평균 차이 > 0.1이면 1
  - S2: 유량 차이 > 0.1이면 4/7, Acc2 차이 > 0.3이면 3/7을 더함
  - 50초 간격으로 "처음~t 누적 평균"과 "t 이후 50초 평균"을 비교
- 결론: 테스트 5개 중 3개에서 변화점 탐지
- 향후 과제로 적은 것: adaptive threshold, 구간별 동적 특징, RNN 같은 시계열 딥러닝

## HW4 재평가 — 문제

- 변화점 부근만 확인했기 때문에, 그 이전에 이미 HF가 최댓값에 도달한 오경보가 집계되지 않았음

| 테스트 파일 | 실제 변화점 | HW4 첫 탐지 | 판정 |
|---|---|---|---|
| v1_2 | 666초 | 150초 | 516초 앞선 오경보 |
| v1_3 | 600초 | 100초 | 500초 앞선 오경보 |
| v1_4 | 600초 | 400초 | 200초 앞선 오경보 |
| v1_7 | 600초 | 700초 | 100초 늦게 탐지 |
| v2_1 | 600초 | 650초 | 50초 늦게 탐지 |

- **실시간 판단 불가:** 시각 t 판단에 t 이후 50초를 사용 → 구조적으로 최소 50초 늦음, "사전 탐지"가 될 수 없음
- **정규화 누수:** 테스트 데이터를 테스트 자신의 평균·표준편차로 정규화 → 운용 중엔 알 수 없는 미래 정보
- **오경보 미집계:** 성공률 3/5가 실제보다 높게 계산됨
- **수작업 설계:** 가중치·임계값을 일부 파일 평균 차이로 정함, 누적 평균이라 시간이 지날수록 변화가 묻힘, 50초 단위로만 검사, 보고서엔 S1이 "감소 여부"였지만 코드는 절댓값
- **정량 평가 부재:** 성공/실패만 판단, 탐지 지연·오경보율·F1 없음

## v2 — 설계

- **전처리**
  - 1초 재색인 + 선형 보간, 5초 이상 연속 결측은 `big_gap`으로 표시 → 보간 구간 알람은 오경보에서 제외
  - anomaly 라벨은 직전 값으로 채움, 이상 시작(onset) = anomaly가 0→1로 바뀌는 첫 시점
- **누수 없는 정규화**
  - 기준선: 각 파일 앞 300초 중앙값 ("가동 후 5분은 정상" 가정 → 실시간으로 계산 가능)
  - 스케일: 학습 fold 파일들의 정상 구간 표준편차 중앙값 (테스트 정보 미사용)
  - Current·Voltage 글리치(예: 240 A) 때문에 ±10으로 clip
- **Causal 슬라이딩 윈도우:** 시각 t에는 [t−59, t] 과거 60초만 사용, stride 1
- **파일 단위 5-fold 교차검증**
  - fold당 테스트 4개, valve2 4개는 서로 다른 fold에 배치
  - 학습 16개 중 3개는 검증용 → 임계값 결정에만 사용
  - 20개 파일 모두 한 번씩 "처음 보는 데이터"로 평가
- **알람 규칙·임계값 (목표 B)**
  - 점수가 임계값을 3초 연속 넘으면 알람 (순간 노이즈 억제)
  - 임계값 = 검증 파일에서 `평균 탐지 지연 + 120 × 파일당 오경보 수` 최소값 (오경보 1회 = 120초 지연이라는 설계 가정)
- **목표 A 설계 (시간 누수 차단)**
  - 300초 ~ 이상 직전의 정상 구간만 사용, 이상 시작 H초 전 이내면 1 (H = 10, 30, 60, 120초)
  - 윈도우마다 센서 평균을 빼서(window demeaning) 절대 수준 제거 → 형태 변화만 보게 함
  - 경과 시간 하나만 쓰는 대조 모델(Time-only control) 함께 학습
- **평가 지표**
  - 이벤트: 탐지 여부, 탐지 지연(이상 시작 → 첫 알람), 오경보 수(300초~onset에서 새로 켜진 알람)
  - 시점: ROC-AUC, PR-AUC, Precision/Recall/F1 (300초 이후 구간)
  - 목표 A: 5-fold out-of-fold ROC-AUC
- **모델 설정**

| 모델 | 입력 | 방식 | 설정 |
|---|---|---|---|
| M1 Logistic Regression | 윈도우 통계특징 56개 | 지도 | StandardScaler + L2(C=0.5), class_weight=balanced |
| M2 LightGBM | 윈도우 통계특징 56개 | 지도 | 트리 300개, lr 0.05, leaves 31, subsample 0.8 |
| M3 1D-CNN | 원시 60초 × 8센서 | 지도 | Conv1d 32-64-64(k=5)+BN+ReLU → [전체 평균 ‖ 최근 10초 평균] → FC, BCE(pos_weight), 15 epoch |
| M4 LSTM-AE | 원시 60초 × 8센서 | 비지도(정상만) | LSTM(64) → 잠재 16 → LSTM(64), MSE 25 epoch, 점수 = 최근 10초 복원오차 |

- 윈도우 통계특징: 센서마다 최근 10초 평균, 윈도우 평균, 최근 10초 − 이전 50초 평균 차이(HW4의 S1·S2 일반화), 표준편차, 기울기, 최솟값, 최댓값 → 8 × 7 = 56개
- 공통: Adam lr 1e-3, seed 고정, 노트북 CPU 약 10분, Python 3.12 + PyTorch + scikit-learn + LightGBM

- LSTM-AE는 오경보 최소(2회)지만 3개 파일(v1_0, v1_2, v1_4) 미탐지, 지연 100–330초인 파일도 있음 → 오경보와 속도의 trade-off

- **v2_1 (HW4에서 유일하게 성공에 가까웠던 파일):** 모든 모델이 640–676초에 알람. 지도학습 모델은 이상 구간 내부 결측에서도 알람 유지, LSTM-AE는 보간 구간에서 점수가 떨어져 먼저 꺼짐

## v2 — 결과: 왜 탐지에 약 30초가 걸리나 (정렬 분석)

- 20개 파일을 이상 시작 시점(0초)에 맞춰 정렬하고, 시점별 알람 비율과 센서 중앙값을 비교
- RateRMS(유량)는 이상 시작 후 약 10초부터 떨어지기 시작해 50–65초 사이에 급락
- RateRMS 10초 평균이 정상 범위(−1.5σ)를 처음 벗어나는 시점: 중앙값 39초 (최소 5초, 최대 65초, 평균 34.6초)
- 알람 비율 곡선이 이 유량 하락 곡선과 같은 시점에 올라감
- → 지연의 대부분은 모델 한계가 아니라 **밸브를 닫은 뒤 유량이 실제로 줄어드는 물리적 반응 시간**
- 0초 이전에는 어떤 센서도, 어떤 모델의 알람 비율도 의미 있게 올라가지 않음 → 목표 A 결과와 일치

- 해석
  - SKAB에는 이상 이전의 물리적 전조가 없음 — 이상은 사람이 밸브를 닫는 순간 시작
  - 이 데이터에서 "사전 예측 성공"이 나오면 시간 정보 누수일 가능성이 높음
  - HW4에서 본 "변화점 1분 전 Voltage outlier", "3분 전 Temperature 감소"는 일부 파일의 우연한 패턴이었고 일반화되지 않음

## v2 — 추가 분석: HW4의 센서 선택 검증

- 각 센서를 무작위로 섞었을 때 PR-AUC 하락량(permutation importance)을 5 fold 평균
- **RateRMS 선택 → 옳았음:** 4개 모델 모두 중요도가 RateRMS에 집중 (0.34–0.48), 나머지 7개는 모두 0.03 미만
- **Accelerometer2RMS(가중치 3/7) → 근거 없음:** 모든 모델에서 중요도 ≈ 0 (−0.005–0.009)
  - HW4의 PCA는 파일마다 "분산이 큰 방향"을 찾았을 뿐, "정상과 이상을 가르는 방향"이 아니었음 → Acc2의 큰 노이즈 분산이 중요해 보였던 것
- LogReg 계수는 Temperature·Thermocouple에도 분산됐지만 permutation 중요도는 ≈ 0 → 상관된 특징끼리 가중치를 나눠 가졌을 뿐
- **PCA vs LSTM-AE 잠재공간 (fold 0 테스트 4개)**
  - 2D 선형 분리도는 비슷 (로지스틱 회귀 AUC 0.792 vs 0.786)
  - PCA는 정상·이상이 한 덩어리로 겹침, LSTM-AE 잠재공간은 시간 흐름이 연속 궤적으로 나타나고 이상 구간이 별도 궤적
  - → AE의 장점은 한 시점의 분리도가 아니라 시간 구조를 학습해 정상과의 차이를 점수화하는 것

## 결과를 믿을 수 있게 한 장치

- 정규화 누수 차단: 기준선은 각 파일 앞 300초, 스케일은 학습 fold 통계
- 파일 단위 교차검증: 같은 파일의 윈도우가 학습·테스트에 동시에 안 들어감, 임계값도 별도 검증 파일에서 결정
- 시간 누수 대조군: Time-only 모델로 누수 크기를 직접 측정(AUC 1.0), demeaning으로 제거한 상태에서 평가
- 물리적 해석: 탐지 지연(약 30초)과 유량 반응 시간(중앙값 39초) 일치 → 모델이 우연이 아니라 실제 신호에 반응
- 재현성: 모든 seed 고정, 처음부터 두 번 다시 실행해 같은 수치 확인

## 한계

- 파일 20개, 파일당 이상 1회 → 통계적 신뢰구간이 넓음
- 같은 날·같은 운전 조건의 밸브 폐쇄 이상만 다룸 → 다른 운전 조건(anomaly-free, 유량 4배)으로의 일반화 미검증
- 임계값 비용(오경보 1회 = 120초)은 설계 가정 → 현장 비용에 맞춰 조정 필요
- v1_2 지연 0초는 보간 구간에서 알람이 켜진 값이라 실제보다 유리함

## 결론

- 목표 B 즉시 탐지 → **달성:** LightGBM이 처음 보는 20개 파일을 과거 60초만 보고 모두 탐지, 지연 중앙값 30.5초, F1 0.867. 지연은 물리적 반응 시간에서 비롯
- LSTM-AE는 느리지만 오경보 2회 → 이상 라벨이 없는 현장의 대안
- 목표 A 사전 예측 → **불가능:** 누수를 제거한 모든 모델이 무작위 수준, 경과 시간만 쓴 대조 모델은 AUC 1.0. 현실적인 목표는 "사전 탐지"가 아니라 "최소 지연 탐지"
- 부정적 결과지만 누수를 통제한 실험으로 근거를 갖춘 결론이라는 점이 의미
- HW4 센서 선택 검증: RateRMS는 옳았고 Acc2 가중치는 근거 없음 → 비지도 차원축소로 feature를 고를 때의 한계
- 향후: LightGBM + LSTM-AE 앙상블, 운전 조건 변화에 대응하는 도메인 적응, SKAB의 다른 이상 유형(other 폴더)으로 확장

## 배운 점

- 성능 숫자보다 **평가 방식이 먼저**. 같은 문제도 미래 데이터·정규화 누수·오경보 미집계를 바로잡으니 결론이 완전히 바뀜
- 데이터가 만들어진 방식(이상이 항상 600초)을 모르면 모델은 신호가 아니라 지름길을 배움 → 대조군으로 누수를 직접 재는 것이 가장 확실한 확인
- 내가 낸 결과를 다시 의심하는 것이 개선의 출발점 (HW4 → v2)
- "불가능하다"는 부정적 결과도 실험 설계가 탄탄하면 의미 있는 결론
- PCA로 고른 feature는 "분산이 큰 것"이지 "중요한 것"이 아닐 수 있음 → 모델 기반 중요도로 검증
- 탐지 지연 같은 숫자는 물리적 의미와 맞춰 볼 때 설득력이 생김
- 수업의 이론(교차검증, ROC, Statistical Sins)이 실제 판단 근거로 쓰임
