## 개요

센서빅데이터처리 수업의 파이널 프로젝트입니다. 공개 데이터셋 **SKAB(Skoltech Anomaly Benchmark)** 의 물 순환 설비에서 밸브를 닫아 만든 이상(valve1 16개, valve2 4개, 총 20개 파일, 1 Hz · 8개 센서)을 다뤘습니다.

- **HW4 (수업, 2026.05.28 – 06.17):** 시각화·PCA·미분 분석으로 핵심 센서를 고르고, 직접 정한 가중치와 임계값으로 "Hyper Feature"를 만들어 변화점을 탐지했습니다.
- **v2 (수업 후 개인 후속, 2026.11.20):** HW4의 각 단계를 학습 모델로 바꾸고, 평가 방식의 문제를 바로잡아 다시 검증했습니다.

질문은 두 개로 나눴습니다.

- **목표 A — 사전 예측:** 과거 데이터만 보고 "H초 뒤 이상이 시작될지" 맞힐 수 있는가?
- **목표 B — 즉시 탐지:** 이상이 생기면 최소 지연·최소 오경보로 알람을 낼 수 있는가?

## HW4를 다시 보니

오경보까지 포함해 다시 평가하자, 테스트 5개 중 3개를 탐지했다던 결과가 실제로는 **1개만 성공에 가까웠습니다.** 원인은 이랬습니다.

| 문제 | 내용 |
|---|---|
| 미래 데이터 사용 | 시각 t 판단에 t 이후 50초를 사용 → 실시간 불가, 최소 50초 지연 |
| 정규화 누수 | 테스트 파일을 자기 평균·표준편차로 정규화 |
| 오경보 미집계 | 변화점 부근만 확인 → 200–516초 앞선 오경보를 놓침 |
| 수작업 설계 | 가중치·임계값을 손으로 정하고 누적 평균 사용 |
| 시간 누수 위험 | 20개 중 18개 파일에서 이상이 정확히 600초에 시작 |

## 어떻게 다시 만들었나

| HW4 단계 | v2 대체 방법 |
|---|---|
| PCA (선형 차원축소) | LSTM-Autoencoder — 정상만 학습, 복원 오차를 이상 점수로 |
| 손으로 정한 선형결합 | Logistic Regression |
| 손으로 정한 규칙 | LightGBM (윈도우 통계특징 56개) |
| 눈으로 본 패턴 | 1D-CNN (원시 60초 × 8센서) |
| 눈으로 고른 센서 | Permutation Importance로 검증 |

- **실시간 구조:** 과거 60초만 쓰는 causal 슬라이딩 윈도우
- **누수 차단:** 기준선은 각 파일 앞 300초 중앙값, 스케일은 학습 fold 통계
- **파일 단위 5-fold 교차검증:** 20개 파일이 모두 한 번씩 "처음 보는 데이터"로 평가됨. 임계값은 별도 검증 파일에서 `평균 지연 + 120 × 오경보` 비용이 가장 작은 값으로 결정
- **결측 처리:** 5초 이상 결측은 표시해 두고, 보간 구간에서 울린 알람은 오경보에서 제외
- **시간 누수 대조군:** 사전 예측 실험에서 윈도우마다 평균을 빼고, 경과 시간만 쓰는 대조 모델로 누수 크기를 직접 측정

## 결과

**즉시 탐지 (목표 B) — 달성**

| 모델 | 탐지 파일 | 지연 중앙값 | 오경보 | F1 |
|---|---|---|---|---|
| Logistic Regression | 20/20 | 30.5초 | 21 | 0.778 |
| **LightGBM** | **20/20** | **30.5초** | **9** | **0.867** |
| 1D-CNN | 20/20 | 40.0초 | 8 | 0.823 |
| LSTM-AE (정상만 학습) | 17/20 | 64.0초 | 2 | 0.604 |

이상 시작 시점 기준으로 20개 파일을 정렬해 보니, 약 30초의 지연은 모델 한계가 아니라 **밸브를 닫은 뒤 유량이 실제로 줄어들기까지의 시간(중앙값 39초)** 과 일치했습니다.

**사전 예측 (목표 A) — 이 데이터로는 불가능**

센서를 쓰는 모든 모델의 AUC는 0.41–0.58로 무작위 추측과 같았고, 경과 시간만 쓴 대조 모델은 0.99–1.00이었습니다. SKAB의 이상은 사람이 정해진 시각에 밸브를 닫아 만든 것이라 물리적 전조가 없습니다. "미리 맞혔다"는 결과가 나온다면 시간 정보가 새어 들어갔을 가능성이 높다는 뜻입니다.

**HW4 센서 선택 검증:** RateRMS(유량)를 고른 판단은 옳았지만(모든 모델에서 중요도 집중), Accelerometer2RMS의 가중치는 근거가 없었습니다. PCA는 분산이 큰 방향을 찾을 뿐, 정상과 이상을 가르는 방향을 찾지 않기 때문입니다.

## 배운 점

- 성능 숫자보다 **평가 방식이 먼저**입니다. 같은 모델도 미래 데이터·정규화 누수·오경보 미집계를 바로잡자 결론이 완전히 달라졌습니다.
- 데이터가 만들어진 방식(이상이 항상 600초에 시작)을 모르면 모델은 신호가 아니라 지름길을 배웁니다. 대조군으로 누수 크기를 직접 재는 것이 가장 확실한 확인 방법이었습니다.
- "예측은 불가능하다"는 부정적 결과도, 누수를 통제한 실험으로 근거를 갖추면 의미 있는 결론이 됩니다.

## 한계와 다음 단계

- 파일 20개, 파일당 이상 1회뿐이라 신뢰구간이 넓고, 운전 조건이 다른 데이터로의 일반화는 검증하지 못했습니다.
- 다음에는 빠른 LightGBM과 오경보가 적은 LSTM-AE를 결합한 앙상블, 운전 조건 변화에 대응하는 도메인 적응을 시도해 볼 수 있습니다.
